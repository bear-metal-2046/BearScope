Get started

BearScope brings the PathPlanner editor and robot log replay into one desktop app. Use the editor to plan an auto, then use 2D Field to compare the plan with a recorded run.

  1. On Windows, extract the entire BearScope ZIP and open BearScope.exe.
  2. Click + in the tab bar and choose PathPlanner. Click Open Robot Project and select the root of your robot project.
  3. In 2D Field, expand PathPlanner and click Load Current Project. Pick a path or auto from the route list.

PathPlanner Help in the editor opens this guide. You can also add it from the + menu.

Edit paths and autos

Use the PathPlanner tab to create paths and autos, adjust waypoints, rotation targets and constraints, and add event markers. The project drawer also opens robot settings, the navigation grid, and the telemetry view. Changes saved in the editor go into the robot project's deploy folder.

Quick waypoint edits in 2D Field

The quick editor supports PathPlanner's 2025.0 file format. It edits waypoint geometry and preserves constraints and event markers. Export your copy before selecting another set of files or closing the tab.

  1. In the 2D Field PathPlanner panel, use Open files… or Open folder… to import a copy. To load an auto, include all referenced paths.
  2. Select an individual path. Drag a waypoint or its handles on the field, or enter coordinates in meters. Locked waypoints stay in place.
  3. Click Export .path copy. Place the exported file in your project's paths folder when you're ready to use it. Preserve its filename if an auto references it.

Adds available PathPlanner current pose, target pose, and active path topics to Poses from a live connection or a log.

The orange line shows the authored route. Choose the correct FRC field and alliance transform. Match the rotate or mirror option to your robot's PathPlanner configuration when reviewing a red-alliance run.

Build a manual comparison route

Use this when your robot code combines or transforms paths at runtime. Load the project in 2D Field → PathPlanner first.

  1. Expand Manual comparison route and click Add path segment for each path the robot ran. Select the file in each row. You can add the same file more than once.
  2. Use Move up to match the order in your robot code. Remove deletes a row from the comparison.
  3. Set the flips and rotation for each segment. Flip X reflects across the middle of the field length. Flip Y reflects across the middle of the field width. Flips happen first, then rotation around field center. Positive angles turn counterclockwise in blue-origin field coordinates.
  4. Open Replay analysis and enable Show recorded trail and tracking error. The orange segments use your manual transforms, and the cyan trail stays in the logged position. The waypoint picker uses the transformed positions and labels each waypoint with its segment number.

For example, if your code runs one path as written and then mirrors a second path lengthwise, add both in order and enable Flip X on the second only. For a 180° turn about field center, enter 180 with both flips off.

The manual route applies to the overlay and waypoint comparison. The tracking-error plots still compare logged currentPose and targetPose. The manual route uses only field-center transforms and draws each segment separately. It does not generate connector paths or infer timing from robot code.

Clear Use manual comparison route to return to the standard path or auto and alliance preset. Manual settings stay in this tab while it is open and do not change project files.

Analyze a replay

Open a robot log, select the route used for that run, and expand 2D Field → PathPlanner → Replay analysis.

Planned vs. actual

Enable Show recorded trail and tracking error. The cyan trail is the recorded robot motion. Scrub the main timeline to move the cursor through the position error plot in meters and the absolute heading error plot in degrees.

Record blue-origin /PathPlanner/currentPose and /PathPlanner/targetPose as WPILib Pose2d fields. Error uses the latest target at or before the actual sample. With current pose alone, you can still see the trail.

Auto events

Record command activity as boolean fields under CommandsUnique, CommandsAll, or /PathPlanner/Events. Click a recorded start or finish to jump to that point in the log. A planned marker with an exact logged name match jumps to the first recorded start. The list shows the first 200 recorded transitions.

Waypoint comparison

Choose a waypoint under Compare waypoint across runs. Each result shows the closest recorded sample and its distance from that waypoint. Click it to jump to the sample. With robot-mode data, results use autonomous intervals. Otherwise, each recorded pose series counts as one run. Merge aligned logs in BearScope to compare several matches.

Example: If a waypoint result is 0.28 m away, the closest logged pose in that run was 28 cm from the waypoint. It measures distance to the pose sample.

Troubleshooting

The PathPlanner tab is missing or blank
Use the full Windows desktop build. If the editor reports a failure, click Retry. If the tab still looks wrong after an update, close BearScope and reopen the new build.
Load Current Project says to open a project
Open the robot project in the editor first, then return to 2D Field and click the button again.
An auto is missing paths
Check that every path referenced by the auto is present and that the file names match. Load the whole deploy folder to include both paths and autos.
No error graph or event jumps
Check the log for target pose and boolean command telemetry. A planned event marker without a logged match has no timestamp.

Run from VS Code

Open the BearScope source folder, save your edits, and press F5. Choose Run BearScope with PathPlanner if prompted. The task compiles the app and prepares the Windows editor. Close the running copy before rebuilding the native helper.

With dependencies installed, you can also run these from the VS Code terminal:

npm.cmd run compile
npm.cmd run pathplanner:prepare
npm.cmd start

The Dart editor lives in pathplanner/lib. The repository README includes the Flutter build commands. This guide lives in www/bearscope-docs.html. Update it when a BearScope feature or workflow changes.
